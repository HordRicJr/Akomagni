# Internationalization (i18n) policy

Akomagni follows the documentation practices of large successful OSS projects
(VS Code, React, Rust): **canonical English** with **mirrored translations**.

## Supported languages

| Code | Language | Status |
|------|----------|--------|
| `en` | English | Canonical — write here first |
| `fr` | French | Required mirror |

Future languages may be added via community contribution (open an issue first).

## File mapping

| English (canonical) | French mirror |
|---------------------|---------------|
| `README.md` | `README.fr.md` |
| `CONTRIBUTING.md` | `CONTRIBUTING.fr.md` |
| `CODE_OF_CONDUCT.md` | `CODE_OF_CONDUCT.fr.md` |
| `docs/en/<page>.md` | `docs/fr/<page>.md` |

**Not translated** (English only unless noted):

- `CHANGELOG.md` — entries in English; major releases may add FR summary
- `SECURITY.md` — security contact must stay consistent
- Source code comments — English preferred
- CLI output — English default; FR planned via config

## Contributor rules

1. **User-facing doc change** → update EN **and** FR in the same PR.
2. **Code-only change** → update EN architecture doc if behavior changes; FR mirror required.
3. **Cannot translate now?** → open issue labeled `i18n` within 48 hours; do not merge without maintainer approval.
4. **New doc page** → create both `docs/en/foo.md` and `docs/fr/foo.md`; link from both indexes.

## Review checklist (maintainers)

- [ ] EN doc updated
- [ ] FR doc updated (or `i18n` issue linked)
- [ ] `docs/README.md` links valid
- [ ] `CHANGELOG.md` updated for user-visible changes
- [ ] Root README badges/links still work

## Translation style

- Keep technical terms consistent: **Akomagni Flow**, **Akomagni Memory**, **Akomagni Train**
- Do not translate: CLI commands, file paths, agent names (Mary, John, etc.)
- French: use *tu* in user guides (informal, creator audience)

## Automation (planned)

- CI check: warn if `docs/en/` and `docs/fr/` file lists diverge
- PR template reminder for i18n
